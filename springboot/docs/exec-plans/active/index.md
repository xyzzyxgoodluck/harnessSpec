## 2. 计划文件骨架（★=必填）

1. ★ 目标与**完成判据**：可验证（命令 / 测试名 / curl 期望 / 指标），不写"基本完成"。
2. ★ 范围：In / Out 清单 + 前置条件（依赖的环境、数据、其它计划）。
3. ★ 步骤清单：每步含"做什么 + 怎么验证（命令或检查项）"，一步一验证。
4. ★ 进度日志（接力区）：`日期 | 阶段 | 结论 | 证据 | 下一步`，**只追加不改写**——下一个代理据此接续。
5. ○ 风险与回退：可能失败点、回退方式（含 DB 迁移与缓存/MQ 兼容考虑）。
6. ★ 收尾：完成判据逐条核对结果 + 归档结论 + 关联需求/ADR/技术债的更新位置。

> 纪律：证据优先（命令输出、测试结果、PR 记录）；未验证的步骤不得标"已完成"；结论变化追加新日志行并说明原因。
