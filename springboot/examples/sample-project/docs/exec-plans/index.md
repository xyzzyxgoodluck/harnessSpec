# exec-plans —— 执行计划与技术债台账

> 服务**多轮 / 多代理任务**：长周期改造在这里接力进度，下一个代理不必从头摸索；归档防熵（`active/` -> `completed/`）。
> 固定组成部分：**目录必建**（含本文件、`active/`、`completed/`、`tech-debt-tracker.md`）；计划文件按触发器写入。
> 分工不重复：`../product-specs/` = 做什么/验收标准、[`../design-docs/index.md`](../design-docs/index.md) = 为什么这样定、本目录 = **怎么推进与当前进度**。

## 结构

```text
exec-plans/
  index.md               # 本文件：计划索引 + 状态流转
  active/                # 进行中计划（每个计划一个文件，模板见 active/index.md）
  completed/             # 已归档计划（只读，归档即冻结）
  tech-debt-tracker.md   # 技术债台账（发现即登记，闭环后标记）
```

## 状态流转

`待办 -> 进行中 -> 阻塞 -> 已完成 / 已放弃`

> 阻塞不等于失败：在计划文件「进度日志」写明阻塞原因、已尝试方案与需要的决策，并登记到本表「阻塞」列。

## 触发器（条件满足即必须写入内容）

| 触发条件 | 必须写入 |
| --- | --- |
| 任务跨多轮 / 多代理接力，或一次改造涉及多模块且无法一轮完成 | `active/{{YYYYMMDD}}-{{简述}}.md` + 在本表登记 |
| 发现技术债（性能、重复实现、缺失测试、临时方案） | `tech-debt-tracker.md` 追加一行 |
| 计划完成 / 放弃 | 文件移入 `completed/` + 本表状态回写 + 关联需求状态同步 |
