# 元规范（Meta-Spec）：本仓库规范的模型与权威关系

> 用途：定义"规范由什么构成、谁在哪个主题上是权威、规则怎么标识与分级、元规范自身如何验收"。**只定义模型，不写细则**——细则在 §3 权威矩阵指向的文件里。
> 读者：撰写/修订任何规范的人与 AI 编码代理；本仓库维护者。任何规范改动开始前先读本文。
> 层级：本文件是 L1 元规范的入口，与其他 L1 文件共同构成"规范之规范"（§2）。

## 1. 术语（本仓库内一律按此用词，不再造同义词）

| 术语 | 定义 |
| --- | --- |
| **元规范** | 规定"如何编写规范"的规范：`docs/` 下 §2 所列的 L1 文件集合。 |
| **规范** | 对某个类型或项目"必须/应该怎么做"的成文约束。类型规范 = `<类型>/AGENTS.md` 与 `<类型>/docs/**`。 |
| **模板** | 可复制到真实项目的规范原件；本仓库的类型目录即模板。 |
| **范本** | 模板中随复制进入真实项目的具体文件（如 `docs/CODING_STANDARDS.md`），内容是"待裁剪的规则 + 示例"。 |
| **样例** | 用来**检验**规范的项目（`<类型>/examples/sample-project/`）；不是交付物，不随模板复制。 |
| **交付物** | 模板对外产出物 = `<类型>/AGENTS.md` + `<类型>/docs/**`（+ 可选 `README.md`）。 |
| **规则** | 规范中一条可判定的约束，带级别与 ID（§4）。 |
| **不变量** | 交给机器强制的规则（工具/测试拦得住），与"仅评审"相对。 |
| **强制者** | 拦住违规的具体手段：工具配置 / 架构测试 / 注册表测试 / 评审；登记在 [`enforcement-map.md`](enforcement-map.md)。 |
| **判据** | 判定一条规则是否被满足的可执行检查：脚本 FAIL、脚本 WARN（需人工确认，**不算强制**）或人工核对步骤。 |
| **符合性等级** | 规则的级别：必须 / 应该 / 可以，判定标准见 §4。类型级验收用 L1–L5，元规范自身用 M0–M3（§6）。 |
| **豁免** | 明确声明某条固定要求对某对象不适用；必须记 ADR（如 [`decisions.md`](decisions.md) ADR-005）。 |

## 2. 分层（谁约束谁）

```text
L0 依据      harness-principles.md    # 外部经验摘编：解释"为什么这样组织"，本身不产生约束
L1 元规范    meta-spec.md（本文件）    # 模型：术语 / 分层 / 权威矩阵 / 规则 ID 与级别 / 验收
             fixed-docs.md            # 六个固定组成部分的细则全文
             authoring-types.md       # 类型编写流程、AGENTS 骨架、交付结构、L1–L5 验证协议
             writing-standards.md     # 一切文档的写作与命令书写规范
L2 类型规范  <类型>/AGENTS.md + <类型>/docs/**   # 交付物；对真实项目的唯一权威
L3 项目实例  真实项目根                           # 由 L2 复制落地后按团队裁剪
```

- 约束方向自上而下；**冲突时以更具体者优先**（L3 > L2 > L1 > L0），冲突须记 ADR，禁止静默取舍。
- **记录类文件不参与约束**，只登记事实：[`enforcement-map.md`](enforcement-map.md)（强制者映射）、[`decisions.md`](decisions.md)（ADR）、[`changelog.md`](changelog.md)（版本历史）。
- 本仓库自身是"规范汇编"，不是采用模板的真实项目，故对部分固定要求有**显式豁免**（见 ADR-005）；下游**不得照抄本仓库根布局**。

## 4. 规则标识与级别

- **ID 形式**：`<AREA>-<节>[.<序>]`，AREA 取文件代号：`MS`（本文件）、`FD`（fixed-docs）、`AT`（authoring-types）、`WS`（writing-standards）。例：`FD-6.1` = fixed-docs §6 第 1 条；`AT-2.5` = authoring-types §2 第 5 章规则。
- ID **一经分配不复用、不因插入而改变**；引用规则时用 ID，不写"某文件 §N 那一条"。
- 级别与判定标准：

| 级别 | 含义 | 判定标准 | 是否必须登记强制者 |
| --- | --- | --- | --- |
| **必须** | 违反即不合格 | 有可执行判据（脚本 FAIL），或明确、可复核的人工步骤 | **是**：有强制者，或显式标「仅评审」+ 理由 |
| **应该** | 推荐，允许有理由的偏离 | 偏离须在 PR/MR 或 ADR 写明理由 | 否；一旦被当既成事实引用，则须登记 |
| **可以** | 可选做法 | — | 否 |

- 级别只能由维护者提升；提升须在 [`changelog.md`](changelog.md) 登记，并同步补强制者或标「仅评审」。

## 5. 一份 L1 元规范文档必须遵守的骨架

1. 标题 + `>` 块：**用途 / 读者 / 何时读**（各一行）
2. 规则正文（分级；条目尽量带 ID）
3. **边界**：本文件不重复什么、细则指向哪里
4. 维护与变更：谁能改、记在哪里

- 规模：本文件 ≤120 行，其余 L1 文件 ≤200 行（超出即拆或下沉到 L2 范本）；文件名小写 kebab-case。
- 结构描述用纯缩进，禁用画线字符；占位符配平；不进环境准备类内容。

## 6. 元规范自身的验收（M0–M3）

| 级 | 内容 | 现状 |
| --- | --- | --- |
| **M0 静态** | 本文件与各 L1 文件的结构、链接、占位符、画线字符 | `scripts/validate-repo.ps1`（L1′）已覆盖 |
| **M1 一致性** | 权威矩阵每主题唯一；规则 ID 唯一且无孤儿；脚本内清单项数 = 权威文件列出的项数；跨文件引用有效 | **待实现（P2）**；当前由 L1′ 覆盖其中"链接 / `§N` 引用"两部分 |
| **M2 可证伪** | 每条「必须」级元规则都有强制者或显式「仅评审」；凡声称"已强制"须亲手造违规验证 | 部分落地（`enforcement-map.md` §2.4） |
| **M3 生效抽查** | 每次实质规范变更，抽查 ≥1 条元规则的判据，故意违规证明会红后还原 | 惯例已执行（见 v3.3 概览章判据实测） |

## 7. 维护

- 改本文件 = 改规范模型：须记 ADR + [`changelog.md`](changelog.md)；**不得**只在某一份 L2 文件里改口径。
- 新增 L1 文件须：在 §2 分层与 §3 权威矩阵登记、遵守 §5 骨架、登记 `changelog.md`。
- 存量迁移（P1）：L1 文件之间的引用逐步从"§N 散文"改为规则 ID；迁移期间两种写法并存，新写的引用一律用 ID。
